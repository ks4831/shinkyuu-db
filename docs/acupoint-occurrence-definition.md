# 経穴出題データの定義（acupointOccurrences）

経穴統計（`/acupoints`・`/acupoints/unasked`・`/acupoints/[slug]`）の正本は
`src/data/acupointOccurrences.json`。公式過去問（`src/data/pastExams/exam-*.json` の問題文・選択肢・公式正答）を根拠に、
設問ごとに人がレビューした判定を保存する。

- 分析CSVの `studyPoint`（当サイト作成の学習メモ）や `themeId` からは経穴の出題を推定しない。
  旧方式（CSV説明欄の文字検索）は 2026-10 に廃止した。廃止理由は、旧方式で数えた「経穴×設問」399件のうち、
  経穴の知識が実際に問われていたのは約3割だったため。
- 公式過去問JSONには分析用フィールドを追加しない（公式転記データと分析データを分ける）。

## 1. 「出題」の定義

**その設問に正答するために、その経穴の知識（位置・取穴・所属経脈・要穴分類・主治・作用・組合せ・刺鍼・施灸・安全性など）が必要なら、その経穴を「出題された」とする。**

## 2. role（その設問での経穴の立場）

| role | 意味 | 統計 |
|---|---|---|
| `direct` | 経穴そのものが問われている。正答肢の経穴、または問題文の主題になっている経穴 | 数える |
| `required` | 正答そのものではないが、正答を導くのにその経穴の知識が必要（例：問題文の前提「膈兪とともに選穴する」、正答肢の取穴基準「陽陵泉の下約1寸」、「大腸の下合穴が所属する経脈」＝上巨虚） | 数える |
| `distractor` | 誤答の選択肢に登場するだけ（誤答肢の取穴基準として出てくる経穴も含む） | 数えない（保存はする） |
| `ambiguous` | 判断できない。人の再確認が必要 | 数えない（`audit:data` が WARN を出す） |

- 「誤っているのはどれか」形式の問題では、正答（＝誤った記述）の経穴を `direct`、残りの正しい記述の経穴を `distractor` とする。
- 正答肢に2穴の組合せが書かれている場合（例：「肝兪 ── 足臨泣」）は、両方とも `direct` にする。
- 経穴名が経穴以外の意味で使われている場合（例：衝脈の別称「血海」、病理概念「命門火衰」）は、判定に含めず `ignoredMentions` に理由を書く。

## 3. evidence（名称が書かれているか）

| evidence | 意味 |
|---|---|
| `named` | 公式の問題文または選択肢に経穴名（マスタの別名を含む）が書かれている |
| `implicit` | 名前は書かれていないが、部位・要穴分類などから特定が必要（例：34-121 部位だけの選択肢→神門、29-117「脾の大絡の絡穴」→大包） |

role と evidence は別の軸。`implicit` でも正答肢なら `direct` になる。
evidence は公式本文から再現できる必要があり、`audit:data` が照合する。照合ロジックは `scripts/lib/acupoint-text.mjs` にあり、
`俞→兪` の正規化をし、「上腕骨」の中の「腕骨」や「関元兪」の中の「関元」のような部分一致は除外する。

## 4. 数え方

- **出題問題数**：role が `direct` / `required` の設問の数。同じ設問に同じ経穴が何度出ても **1問1カウント**。
- **出題年度数**：出題問題が1問以上ある回（第29〜34回）の数。同じ回に2問あっても **1年度**（例：3問・2年度）。
- **ランキング**：出題年度数の多い順 → 出題問題数の多い順 → 経穴マスタの収録順。
- **未出題**：第29〜34回で、その経穴の `direct` / `required` が0問。誤答肢としての登場（`distractor`）は「選択肢として登場 ○問」として別に表示する。
- 集計の対象は経穴マスタ（`src/data/acupoints.ts`、146穴）で、全361穴ではない。画面にも「収録146穴が対象」と明記する。

## 5. マスタ外の経穴・奇穴

- マスタにない経穴は `{"name": "顴髎", ...}` のように **公式の表記（俞は兪に統一）** で記録し、`outsideMaster` に登録する。
  未登録の名前は `audit:data` が ERROR にする（タイプミスと本当のマスタ外を区別するため）。
- マスタ外の経穴にWHOコードを推測で付けない。将来マスタを拡張したら、その経穴の参照を `name` から `slug` に置き換える
  （マスタ収録穴を `name` で参照すると `audit:data` が ERROR を出すので、置き換え漏れは検出される）。設問単位の判定はそのまま使える。
- 奇穴（十七椎・胆嚢点など）も同じく `name` で記録する。

## 6. データ形式

```json
{ "questionId": "34-121", "examRound": 34, "questionNumber": 121,
  "acupoints": [
    { "slug": "ht7", "role": "direct", "evidence": "implicit" },
    { "name": "三間", "role": "distractor", "evidence": "implicit" } ] }
```

- 候補になった設問は、経穴が1つもなくても `acupoints: []` と `note` で登録する（レビュー済みの記録）。
- 型：`src/lib/acupointOccurrences.ts`。集計：`src/lib/acupoints.ts`（サーバー側で集計し、問題本文はクライアントに送らない）。

## 7. 第35回以降の追加手順

1. `src/data/pastExams/exam-35.json` を追加する（`docs/past-exam-rights-memo.md` の手順）。
2. `npm run extract:acupoints -- --round 35 --out tmp-candidates.json` を実行し、レビュー候補を出す。
   候補は「マスタ経穴名が書かれている」「科目が経絡経穴概論」「問題文・選択肢に 穴/兪/募/井/滎/経脈/経絡 などを含む」「解説にマスタ経穴名がある」のいずれかに当てはまる設問。
   スクリプトは role を自動で決めない。
3. 候補を1問ずつ公式問題・公式正答と照らして判定し、`acupointOccurrences.json` に追記する。
   マスタ外の経穴を新しく使ったら `outsideMaster` にも追加する。
4. `npm run audit:data` を実行する。次のどれかがあると ERROR になる：
   レビュー未登録の候補、本文に名前がある経穴の判定漏れ、evidence と本文の不一致、存在しない slug、未登録のマスタ外の名前。
5. 統計は自動で更新される（`examRounds` と `EXAM_ROUNDS` に35を加えることも忘れない）。
